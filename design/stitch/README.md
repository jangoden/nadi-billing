## Visual system

- Desktop homepage is a 1280 CSS-pixel composition, exported at 2560 pixels. The main container is 1200 pixels including 32-pixel side padding, and navbar/footer containers cap at 1600 pixels.
- Navigation height is 80 pixels. Most desktop sections use 112-pixel vertical padding; the problem and support sections use 96 pixels. Grid gaps are 16, 24, and 48 pixels.
- Surface `#f8f9ff`, alternating surface `#eff4ff`, white panels, foreground `#0b1c30`, secondary text `#434655`.
- Primary `#004ac6`, primary container `#2563eb`, secondary `#00687a`, cyan `#57dffe`, tertiary `#632ecd` / `#7d4ce7`.
- The Network Intelligence section uses `#0b132b` with a `#111c44` canvas, restrained cyan accents, and rose warning panels.
- Tokens specify Plus Jakarta Sans for headings, Inter for body text, and Geist for labels. Desktop hero is 48px / approximately 54px, section headings 32px / 40px, body 16px / 24px, smaller functional copy 12–14px.
- The Stitch screenshot renders some editorial headings with a serif fallback, whereas the exported HTML and project tokens explicitly specify Plus Jakarta Sans. The implementation loads the specified font with `next/font` rather than reproducing the font-loading defect.
- Controls use 8–12px corners, cards 16px, main panels 24px. Ambient shadows are strongest on the hero, pricing, and product preview panels.
- Hero and final CTA have the reference's blue gradients. There are no stock photos. Product previews are HTML UI compositions, not raster screenshots.

## Structure and reusable patterns

The homepage implements navbar → hero → integration strip → problems → four pillars → voucher → billing → network → CRM → comparison → pricing → support → FAQ → final CTA → footer.

Reusable elements include logo, button links, inline SVG icons, section headings, page introductions, card/panel styles, flow steps, navigation data, product preview, capacity selector, and demo explorer.

No separate mobile or tablet screen was available. Mobile rules follow the exported responsive classes and project tokens: stacked split sections, reduced type sizes, 16px phone gutters, 24px tablet gutters, two-column compact cards where appropriate, and a separate mobile navigation disclosure.

## Content reconciliation with task.md

- Approved task copy replaces altered Stitch headlines and claims.
- Removed unverified testimonials, named customer examples, transaction/revenue/uptime figures, operational versions, savings claims, response-time promises, and unsupported detailed integration/security guarantees.
- Kept the visual structure of product illustrations using process labels instead of invented operating data.
- The pricing selector includes all six approved capacities, including Custom. No currency amount is published: `task.md` supplies no approved tariff schedule, and the Stitch example value is not treated as a confirmed business price.
- Legal/company links without supplied pages or content are replaced with relevant working platform/support navigation.
- The exported logo is used once at its intended proportions; the duplicated tiny logo plus text from the generated screenshot is not reproduced.
- No application demo URL was supplied. `/demo` offers an explicitly labeled local process simulation. A real application link can be configured through `NADI_DEMO_URL`.

## Scope of secondary routes

`/fitur` and `/harga` reuse the homepage components to support navigation and CTAs. They are not yet complete ports of their separate Stitch screens. Solution pages are concise foundations; resource pages explicitly disclose that detailed content is being prepared. All nine foundation routes are `noindex` until their content is completed.

Original exports are retained for the next implementation phase. Browser screenshots are generated by `npm run test:e2e` under `test-results/`.
